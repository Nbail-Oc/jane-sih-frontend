# Project Context: Dark Web Threat Actor De-anonymization (SIH / NTRO)

## 1. Original Problem Statement (NTRO, Smart India Hackathon)

Build a system to de-anonymize dark web threat actors by continuously gathering footprints from marketplaces, forums, and the deep web, and linking them to real-world identifying information. Three core capabilities required:

1. **Infrastructure misconfiguration detection** — find misconfigurations in Tor hidden services (exposed server-status pages, SSL certs tied to clearnet domains, default service banners, descriptor inconsistencies) and match them to clearnet infrastructure to point to likely origin servers.
2. **Cross-marketplace entity graph** — map threat actors across multiple marketplaces into a single relationship graph of handles, PGP keys, wallets, and trust links.
3. **AI-based persona linking** — stylometric persona identification and behavioral profiling to link rebranded/migrated personas to known threat actors.

Deliverable: an end-to-end system for collection, storage, contextualization, and querying (via GUI/dashboard) of dark web threat actor intelligence — covering actor profiles, identifiers, infra indicators, persona linkages, attribution confidence, category, last-scan date, and source. Must support export to CSV, JSON, and report formats, and work in a semi-autonomous, continuously-scanning mode.

## 2. Key Strategic Decisions Made So Far

- **Scope approach**: build a thin slice of all 3 pillars + a strong dashboard, rather than going deep on only one — the problem statement explicitly names all three, and SIH judges evaluate against the full spec.
- **Data sourcing decision (important, don't relitigate this without new information)**: we will **not** crawl live, active criminal marketplaces or forums (legal exposure, malware risk, demo instability, no verifiable ground truth). Instead:
  - Pillar 1 (infra) will be tested against **self-hosted `.onion` test services** with deliberately injected misconfigurations (we control ground truth).
  - Pillar 2 (entity graph) will draw on **academic datasets** (e.g. Cambridge Cybercrime Centre's CrimeBB, Gwern's archived marketplace dumps) — real historical data, no live crawling.
  - Pillar 3 (stylometry) will use **synthetic personas with deliberately planted stylistic/identifier links**, so we can prove detection works against known ground truth.
  - A small number of **known-benign real `.onion` sites** (Tor Project's own site, etc.) may be used just to prove the crawler traverses the real Tor network end-to-end.
- **OpSec approach**: recommended Whonix (two-VM: Gateway + Workstation) or Tails for any environment that touches even benign `.onion` addresses — reduces leak risk at the OS/network level rather than relying on app-level proxy config alone.
- **Environment note (from real thesis research, see §4)**: container-level Tor isolation via a Privoxy sidecar + Tor daemon (proxy env vars set at the container level) is a cleaner pattern than per-request proxy config in application code.

## 3. Critical Caution: AI-Research Hallucination Risk

Multiple rounds of "research" in this project were generated by AI tools (not a human team) and produced **fabricated or unverifiable claims**, most notably a GitHub repo called "Argus" that was claimed to already implement our full 3-pillar spec, built for this exact SIH problem statement — this could **not** be confirmed to exist as described and should be treated as fabricated.

**Standing rule for this project**: any AI-tool-generated research (repo names, tool claims, case study details, paper citations) must be treated as an unverified lead, not a fact, until independently confirmed via a live search/fetch that the source actually exists and matches the description. Be especially suspicious of any finding that "perfectly matches" our exact use case.

## 4. Verified Findings So Far

- **Real thesis, genuinely useful (adjacent, not identical)**: Polito & Marra, *"Argus: A Platform for Multi-source Cyber Threat Intelligence Collection and Analysis"* (Master's thesis, AY 2025–2026, advisor Prof. Michele Carminati) — **not** the same as the fabricated GitHub repo above (unfortunate name collision). This thesis does general CTI collection/comparison across sources (not our 3 pillars specifically), but its collection-layer engineering is reusable: container-level Tor isolation (Privoxy sidecar), dynamic `.onion` discovery via trusted directories, incremental crawl state via SQLite, a deliberately-unprocessed raw-storage philosophy for dark web text, and a citable ethical framework (passive/read-only, text-only, no market interaction). Its own Limitations chapter confirms it does NOT do infra fingerprinting for deanonymization, entity-resolution graphs, or stylometric persona linking — i.e., it confirms rather than fills our gap.
- **Real competing SIH submissions found** (worth studying for architecture/data-model ideas): `Sharan112212/darkweb`, `raaj7z/DarkWeb-Deanonymization`, `KhushiBidhuri22/darkweb-attribution` — all built for this same problem statement (SIH 26151).
- **Robin** (`apurvsinghgautam/robin`) — real, verified. Tor-routed search + scrape + LLM summarization + conversational follow-up. Covers only the discovery/search front-end, none of the 3 attribution pillars. Candidate as a discovery-layer component or UX reference.
- A separate large batch of open-source tools/repos was surveyed across 3 AI-generated research passes (covering infra fingerprinting, entity graphs, stylometry, and prior art) — **most of these are still unverified** and need a dedicated verification pass before being trusted or cloned. See the Research Brief artifact for the full raw list.
